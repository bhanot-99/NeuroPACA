What is NeuroPACA?

An AI that watches your computer and learns your brain

Most AI agents wait for you to ask something. NeuroPACA is different — it passively monitors OS-level signals (CPU, RAM, processes, keystrokes) every 60 seconds, detects behavioral patterns like "high focus mode" or "cognitive overload", and stores them in a personal knowledge graph. Over time, it prunes a local language model to match exactly how YOU work — making it faster and more accurate for your specific workflows.

Behavioral graph memory

Agents only fire when a threshold is crossed — zero CPU cost when nothing meaningful is happening.

10-Layer Architecture

Every layer, explained plainly

NeuroPACA is organized into 10 layers. Each layer handles one job. They communicate only through the EventBus — nothing calls anything else directly.

Module dependency heatmap — who talks to whom via EventBus
L2 Sensing
L2 · Reads OS signals every 60s
CPU, RAM, disk, temp, processes, keystrokes. Publishes raw MetricSnapshot to EventBus.
L3 Diagnosis
L3 · Finds patterns in the signals
SignalCorrelator detects FocusSession, HighLoad, Distraction patterns by comparing against thresholds.
L4 Learning
L4 · Updates the knowledge graph
Each signal updates relevance_scores. BeliefPlasticity module adjusts edge weights using co-occurrence.
L5 Drive
L5 · Decides if action is needed
PressureAccumulator builds up score. When threshold hit, it publishes PRESSURE_THRESHOLD_REACHED.
L6 Idle Cog
L6 · Thinks during idle/sleep
DefaultModelNetwork generates insights. Reminiscence replays old nodes. Pruning mask updated.
L9 Interface
L9 · Talks to you
InterfaceLayer surfaces insights to terminal or UI. Handles $, $?, $!, $$ prefix commands.
L10 Orchestrate
L10 · Starts and coordinates everything
NeuroPACAOrchestrator boots all 8 modules, holds singleton references to EventBus, GraphMemory, BitNetRuntime.

⚠ Critical invariants — must not violate

1
EventBus, GraphMemory, BitNetRuntime are singletons — modules hold references to them, they do NOT inherit from them.
2
GraphMemory uses asyncio.Lock, NOT threading.Lock — mixing these will silently deadlock.
3
BitNetRuntime.infer() is blocking — always wrap in loop.run_in_executor() to avoid freezing the event loop.
4
SignalCorrelator produces SIGNAL_CORRELATED; PressureAccumulator consumes it. Never let them call each other directly — always route through EventBus.

Technical Fix

The one broken claim — and how to fix it

The original design claimed graph scores drive pruning at inference time via Ollama. That's architecturally impossible. Here's what the problem is and what to do instead.

❌ The broken claim
# What was claimed: graph_score → pruning_mask pruning_mask → Ollama HTTP call # Ollama serves frozen binary. # You CANNOT reach inside # and skip attention heads. # That API does not exist.
Ollama loads the model as a frozen binary. You send a prompt, you get a response. There is no "skip head 5" parameter in the API. What you described would require loading weights, modifying them in memory, re-serializing, then reloading — that takes seconds, not milliseconds.
✓ The fix — use llama.cpp directly
# Correct implementation: scores = graph_db.query_scores() mask = build_head_mask(scores, domain_to_heads_table) # Apply ONCE at model load model = load_gguf_with_mask( "bitnet-7b.gguf", mask) # Now inference uses your # pruned subnetwork natively.
llama.cpp exposes model internals. Apply the binary head mask once at load time. The sparse subnetwork runs natively at inference — no reload, no latency penalty. Mask only updates when scores change significantly (idle time).

Competitive Position

NeuroPACA vs the field

Feature matrix — NeuroPACA vs Hermes Agent vs OpenClaw
NeuroPACA's moat
Passive OS-level behavioral sensing + personal graph pruning. Nobody else starts from OS signals. Hardware target: laptop CPU, ~1.1GB RAM. Complete privacy — zero cloud.
Hermes Agent's moat
32k stars, v0.18 already, task-execution skill creation loop. Actively shipping. 16+ messaging platforms. Needs 24GB+ VRAM for production use.
The right framing
NeuroPACA isn't a competing agent runtime — it's a behavioral data layer that agents like Hermes could plug into. Build the sensing + graph API as a module, not a product.
